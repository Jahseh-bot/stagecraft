# 本阶段方法编排

先整理角色、要完成的任务、关键场景与术语；列功能模块和依赖，比较首期范围组合，再绘制主流程及失败/恢复状态。确认范围与业务规则后形成带稳定 AC 的规格。需求不是功能名清单：每个模块须有用户价值、输入输出、边界和可执行验收。

先按任务判断适用条件，再实际读取并应用对应方法。无需用户选底层 Skill；也不为了展示数量而加载全部方法。未采用的方法在报告中注明不适用的原因。

## grilling

读取 [grilling](upstream/grilling/SKILL.md)。

适用条件：产品目标、范围或关键方向尚未形成共同理解。

执行要求：先自行调查事实，按决策依赖顺序提出有推荐理由的选项；只追问当前关键分歧，等待用户选择。

验收产物：决策树、关键假设、选项与用户选择来源。

## grill-with-docs

读取 [grill-with-docs](upstream/grill-with-docs/SKILL.md)。

适用条件：需要把产品或方案推敲沉淀成可跨阶段使用的文档。

执行要求：这是组合方法：在当前 agent 中读取同目录 grilling 与 domain-modeling，按下述适配规则执行，不依赖宿主专用 Skill 工具。

验收产物：问题澄清与文档更新同时完成，不能只采访不写文件。

## domain-modeling

读取 [domain-modeling](upstream/domain-modeling/SKILL.md)。

适用条件：出现模糊业务术语、业务规则冲突或难以逆转的真实取舍。

执行要求：结合具体正常/异常场景核对术语与代码；术语明确时及时落文档，重要真实取舍记录 ADR。

验收产物：已确认术语表；符合条件时的 ADR；不把实施细节塞进术语表。

## 技术栈专项方法

按已确认技术栈检查 [技术映射](upstream/technology-skills.json)，读取匹配方法及其必要引用；不自动迁移到某个方法偏好的框架。每个已应用方法必须对应本次具体产物、验证证据或记录的决定，仅列出方法名不算应用。

## 组合方法适配

上游要求调用 Skill 工具时，在无该工具的宿主中直接读取所指的内置 SKILL.md；禁止仅因宿主工具名不同跳过实际方法。采用 grill-with-docs 的阶段同时提供其依赖 grilling/domain-modeling。沿用项目已有术语文档路径；没有时按所附 domain-modeling 版本使用 GLOSSARY.md，避免无意义创建第二份术语表。确认术语即时记录，ADR 仅用于有重要真实取舍的决定。阶段报告链接到这些文件。上游要求全量采访、特定问答格式或强制子代理时，以统一协议的范围、实际选择与宿主能力为准；保留方法实质，不能以适配为理由省略文档与验收。
