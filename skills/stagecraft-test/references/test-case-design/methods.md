# 用例设计方法

## 从规则推导，而不是照抄实现

- 输入分区：对实际定义的类型、范围、格式、空缺和非法值分组，各取有代表性的数据。错误输入是否拒绝、修正或忽略必须有规则依据。
- 边界：在已知阈值附近取边界内、边界上、边界外的数据，注意精度、长度、日期和时区；缺少阈值先讨论，不能拿任意数字当产品标准。
- 条件组合：多个条件共同决定结果时列决策表，识别有效与不可达组合。组合过多时按风险选取并披露未测组合，不能声称抽样是穷举。
- 状态：标出允许/禁止转换、前置角色和失败后的状态；适用时检查重复提交、并发、重试、取消、过期与恢复。预期应覆盖持久化状态和可观察副作用。
- 故障与非功能：按产品实际能力检查依赖失败、断网、权限隔离、数据恢复、兼容性、可访问性或性能。只在授权的环境执行；压力/破坏性故障注入需先明确范围，不直接在生产尝试。

## 风险补全

逐项判断是否适用：角色/权限，空值与非法输入，极端边界，状态转换，重复/并发/幂等，网络与依赖失败，数据持久化与恢复，兼容与可访问性，已约定性能/安全目标，跨模块契约，真实历史缺陷与变更影响。

这是 Stagecraft 的实用检查表，不是原文章未公开的内部清单。标明适用依据；不适用的类别写原因，不生成虚构功能。

## 评审判据

| 检查 | 可接受的结果 | 需修正的信号 |
| --- | --- | --- |
| 需求一致 | 指向明确 AC/规则与版本 | 从现状推断规则、混入未确认功能 |
| 可执行 | 前置条件可建立，数据具体，步骤可复现 | “进行相关操作”、账号/工具不存在 |
| 可验证 | 明确输出、状态或副作用与判定方法 | “显示正常”“性能良好”、空提示文案 |
| 风险价值 | 优先级关联影响与发生条件 | 所有用例最高优先级、遗漏关键失败路径 |
| 不重复 | 每例验证独立风险或分区 | 仅换标题但步骤与预期相同 |

P0 用于阻断核心流程或严重数据/权限问题，P1 用于重要规则/异常，P2 用于较低影响场景；结合产品实际影响与用户确认，不机械套级别。优先级不等于自动跳过低优先级。

## 最小示例：温度换算

已确认 AC-1：摄氏输入 0 时输出华氏 32；AC-2：空输入隐藏结果并提示“请输入温度”。

- TP-1 / TC-1：从空状态输入 0，断言结果 32（按已确认格式检查），不是仅检查组件存在。
- TP-2 / TC-2：先执行 TC-1 再清空，断言旧结果不再显示且出现指定提示，覆盖状态恢复。
- 如果 PRD 未指定低于绝对零度是否允许：提出问题 Q-1，说明“数学换算允许任意数”和“物理温度限制”的取舍，让用户选择；相关 TC 待修订，不先发明拒绝规则。

生成上述用例只完成设计。尚未打开应用或执行断言时，执行状态全部是 not_run。
