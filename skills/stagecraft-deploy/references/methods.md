# 本阶段方法编排

每个阶段开始时先讨论本阶段方案；每个涉及选择的环节执行前，列出 2–3 个实际可行的选项，第一个始终是 agent 最推荐的方案，并解释推荐理由、适用条件与取舍。最后始终提示“如果都不合适，可以直接输入你的想法、约束或组合方案”。等待用户实际回复后再执行依赖该选择的工作；默认选中、沉默和等待超时都不算确认。已有明确选择直接复用，说明依据；用户明确委托的范围按委托执行。 根据已确认目标读取当前平台官方文档与项目配置，形成可执行发布和回滚计划；容器方法只在实际使用容器时启用。真实发布后核对版本、健康与关键路径，失败时诊断、有限修复或按授权回滚。未内置平台专项 Skill 时以官方文档补足，并明确来源与能力限制。

先按任务判断适用条件，再实际读取并应用对应方法。无需用户选底层 Skill；也不为了展示数量而加载全部方法。未采用的方法在报告中注明不适用的原因。

## docker-expert

读取 [docker-expert](upstream/docker-expert/SKILL.md)。

适用条件：已确认部署方案实际使用容器。

执行要求：核对镜像构建、运行配置、健康检查、持久数据与回滚；不得为了用此方法强行引入 Docker。

验收产物：容器配置、构建与健康证据、持久性与回滚验证。

## diagnosing-bugs

读取 [diagnosing-bugs](upstream/diagnosing-bugs/SKILL.md)。

适用条件：测试或运行失败且原因需要定位。

执行要求：复现、缩小范围、建立可证伪假设、验证根因、最小修复后回归；遵循有限尝试预算。

验收产物：复现、根因证据、修复与回归记录。

## 技术栈专项方法

按已确认技术栈检查 [技术映射](upstream/technology-skills.json)，读取匹配方法及其必要引用；不自动迁移到某个方法偏好的框架。每个已应用方法必须对应本次具体产物、验证证据或记录的决定，仅列出方法名不算应用。

## 组合方法适配

上游要求调用 Skill 工具时，在无该工具的宿主中直接读取所指的内置 SKILL.md；禁止仅因宿主工具名不同跳过实际方法。采用 grill-with-docs 的阶段同时提供其依赖 grilling/domain-modeling。沿用项目已有术语文档路径；没有时按所附 domain-modeling 版本使用 GLOSSARY.md，避免无意义创建第二份术语表。确认术语即时记录，ADR 仅用于有重要真实取舍的决定。阶段报告链接到这些文件。上游要求全量采访、特定问答格式或强制子代理时，以统一协议的范围、实际选择与宿主能力为准；保留方法实质，不能以适配为理由省略文档与验收。
