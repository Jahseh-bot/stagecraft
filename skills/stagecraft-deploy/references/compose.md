# Docker Compose 单机部署流程

适用范围：用户明确选择的单台主机及已有应用；不是 Kubernetes、托管云平台或多机高可用方案。

## 准备

检查目标主机上的 Docker 与 Compose 版本、磁盘、端口、网络及目录权限。区分本地准备命令和远端执行命令，不默认当前机器就是部署目标。读取项目已有 Dockerfile、Compose 文件和运行说明，避免重建已有正确配置。

镜像使用可追溯版本或 digest，记录发布前的版本；为持久数据使用明确卷策略，密钥从环境或目标平台密钥设施注入。不要输出解析后的完整敏感配置。配置校验优先 `docker compose config --quiet`，构建日志也需检查密钥泄露。

## 执行与验证

按实际项目生成命令，不把示例当作任意项目都适用：配置校验 → 构建或拉取固定镜像 → 必要且已确认的数据迁移 → `docker compose up -d` → 容器状态与应用健康检查 → 关键用户路径验证。

配置 healthcheck、启动依赖及合理检查时限。HTTP 200 不代表数据库、认证或关键业务路径正常，按应用实际定义烟测。健康检查超时就报告失败或部分完成，保留脱敏日志和镜像版本。

## 恢复

发布前说明旧镜像、旧配置、数据备份和恢复条件。代码回滚可以重新选择旧版本镜像，但仅在数据兼容且操作已授权时执行。不要自动执行 `docker compose down -v`。如果迁移不可逆或缺少已验证备份，明确数据恢复不受保证，停止破坏性重试并交付诊断。

## 完成条件

发布记录包含目标环境、时间、版本、实际执行命令、健康与烟测证据、未覆盖事项，以及可执行恢复方案或无法恢复的具体限制。
