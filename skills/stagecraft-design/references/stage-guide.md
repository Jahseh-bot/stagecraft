# 产品体验与视觉详细工作指引

## 先理解任务，再表现风格

读取PRD/AC、角色、核心任务、现有界面和组件系统。将用户流程映射成页面/视图/操作；先判断信息与交互，再讨论视觉。CLI/API或无界面系统评审其操作/交互契约，不强加UI稿。

## 设计环节

1. **信息结构**：主导航、层级、入口、返回路径、搜索/筛选（存在时）、内容优先级。避免只画首页而遗漏任务闭环。
2. **低保真流程**：用线框或可点击原型走通核心任务、失败与恢复；比较用户操作次数、认知负担和可发现性。先让用户选择有意义的交互方向。
3. **视觉方向**：提供可比较的布局/字体/色彩/图形语言实例，推荐项在前并解释与产品人群的关系。已有品牌和设计系统优先。没有预览能力如实说明，不以一段形容词冒充设计稿。
4. **完整状态**：在已选方向内展开关键页面和组件，覆盖下面状态矩阵。根据任务安排小批次评审，避免所有页面画完才发现方向错误。
5. **响应与可访问性**：描述断点依据、信息折叠/重排、长文案、缩放、键盘/焦点、语义、错误提示位置与减少动效等适用行为。
6. **实现交接**：交付源文件与可见预览、页面/组件ID、设计token、交互规则、资源来源、AC映射、未解决问题，明确哪些是示意与真实交互。

## 页面与组件状态矩阵

| 状态 | 需要说明的行为 | 验证方式 |
| --- | --- | --- |
| 初始/首次使用 | 用户知道下一步，必要引导可跳过或可恢复 | 从空白入口走任务 |
| 空数据/无结果 | 区分尚无数据与筛选无结果，给明确后续动作 | 实际渲染不同空态 |
| 加载/提交中 | 可感知进度、重复触发控制、取消/超时行为 | 慢网或可控模拟 |
| 成功 | 状态变化、反馈、下一步与返回路径 | 操作后观察 |
| 校验失败/服务失败 | 具体原因与恢复动作，不丢用户可保留输入 | 错误场景与重试 |
| 无权限/登录失效 | 解释访问限制并给合适路径，不泄露资源 | 不同角色走查 |
| 内容极端/多端 | 长文字、多语言、极窄/宽视口、触摸/键盘 | 代表尺寸与输入方式 |
| 离线/同步冲突 | 仅当产品支持：可用能力、数据状态、冲突解决 | 对应流程预览 |

## 专项注意

表单标明必填、数据格式、错误位置和提交后的焦点；表格考虑排序/分页/选择/批量操作时的状态；危险操作提供与风险相称的防误触和结果反馈。移动/桌面考虑平台导航、窗口和系统权限；AI界面明确生成中、失败、不确定性及用户修改/撤销路径（适用时）。

资源需说明可使用来源，图标/照片/字体不能凭空宣称授权。重要信息不能只靠颜色、动效或占位文本传达。用已确认内容检查布局，避免用短假文案掩盖溢出。

## 评审与验证

在工具可用时实际渲染、截图和走查关键状态；视觉检查与可访问性自动检查都不等于真实用户研究。没有做的测试明确标注。

展示用户能看懂的实际稿和关键差异，记录意见 → 修改 → 再展示；确认具体版本后才给实现。用户改动流程时重新检查关联页面、AC和接口，不仅改局部颜色。实现阶段发现设计不可行则带证据回到讨论，不能擅自替换视觉方向。
