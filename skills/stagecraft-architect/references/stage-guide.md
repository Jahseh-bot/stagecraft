# 技术方案详细工作指引

## 建立现实基线

读取已评审PRD、设计、仓库约定、依赖与锁文件、运行/部署环境及现有数据。记录相关调用路径、边界与外部契约。对已有系统优先延续可工作的架构；新项目比较满足需求的最小方案，不预设微服务、容器或某个云厂商。

## 架构设计维度

| 维度 | 需要明确的内容 | 验证/交付 |
| --- | --- | --- |
| 系统边界 | 客户端、服务、存储、外部依赖及信任边界 | 系统图与关键链路 |
| 模块职责 | 输入/输出、依赖方向、可测试边界、错误责任 | 模块契约，避免空抽象 |
| 数据模型 | 实体/关系、约束、索引依据、生命周期、迁移 | 数据字典、查询模式与迁移计划 |
| API/事件 | 模式、认证、错误、版本、分页、幂等、顺序 | 契约示例和兼容策略 |
| 状态与并发 | 事务、重复提交、锁/冲突、缓存一致性 | 关键时序和失败恢复 |
| 可靠性 | 超时、重试上限、降级、队列/后台任务、恢复 | 故障假设和验证方式 |
| 安全/隐私 | 授权位置、资源隔离、凭据、输入处理、审计/脱敏 | 威胁场景与控制落点 |
| 性能/成本 | 实际负载假设、预算、瓶颈、资源和第三方调用 | 测量计划、容量假设及未知项 |
| 交付/运维 | 环境、构建、配置、健康、监测、发布/回滚 | 可复现命令、环境差异和操作说明 |

不适用维度说明依据。未知目标先回到产品讨论，不用臆测容量数字指导过度架构。

## 选型与技术探针

按开发速度、团队可维护性、已有生态、部署限制和迁移成本比较可行方案，第一个为推荐方案。保留用户已选技术栈，只有真实证据支持变更时提出替代，不让上游 Skill 偏好代替用户选择。

读取匹配的技术专项方法和官方版本资料。对最危险依赖做隔离探针：认证/接口、构建兼容、查询计划、资源能力等；记录环境、命令、实际结果、失败与仍未验证的假设。不在真实生产上做破坏性探针。

ADR只用于重要取舍：背景、候选、选择、理由、后果、可逆性和复审条件。避免把每个函数命名写成ADR。

## 实施与测试计划

按可验收的垂直切片拆任务，每个任务包含 AC/设计ID、文件或模块、依赖、实现边界、测试方式、运行目录、预期、回滚/关闭方式（需要时）。将数据迁移与兼容过渡列为单独步骤。

确定哪些检查在开发自测、独立测试和部署后完成；使用已有工具，必要新增工具说明理由。CLI/API、移动/桌面、数据任务、AI能力按其实际环境给验证路径，不强制所有项目用浏览器。

## 评审与退出

展示系统/数据图和关键选择、任务顺序、探针证据、风险与成本。用户评审具体技术方案后再落实依赖与大规模实现。

完整性检查：每个AC有实现/测试落点；错误路径有人处理；数据迁移有恢复方式；依赖和版本有依据；未验证假设不写成已验证；技术方案与已评审设计、部署目标一致。重大变更回到相关评审并保留旧方案。
