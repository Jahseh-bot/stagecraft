# 跨阶段覆盖与裁剪

开始每个阶段时用本表建立“适用性矩阵”，随后读取本阶段 stage-guide.md 中相关部分。覆盖面广意味着主动识别遗漏，不意味着给所有项目添加所有功能或工具。用户选产品方案，agent 选适用方法；新增功能、成本、数据用途与发布风险仍须讨论确认。

## 如何裁剪

1. 记录项目形态：新项目/存量改造/缺陷修复；Web/移动/桌面/CLI/API/数据任务/AI产品；单人/多角色/多租户；本地/离线/云端；原型/试点/生产。
2. 用真实输入判断每个维度为适用、不适用或未知，并写依据。未知不是不适用；关键未知先调查，只有用户能回答的业务问题给出推荐选项并等待回复。
3. 小改动按影响精简成果，不重复整个项目的PRD；重大迁移、复杂交易、公开发布按风险加深设计和验证。原型未实现的能力标注为原型，不包装为生产能力。
4. 每项适用维度对应具体产物、检查与责任阶段；不适用写简短理由。只有可观察证据才能关闭检查项，勾选清单不等于验证。

## 适用性矩阵

| 维度 | 需要主动查明的内容 | 常见落点 |
| --- | --- | --- |
| 价值与范围 | 谁在什么场景解决什么问题；基线、成功信号、非目标、替代方案 | discover/spec |
| 角色与权限 | 匿名/登录/管理员、资源所有权、多租户隔离、授权撤销 | spec/design/architect/test |
| 流程与状态 | 主/分支/异常流程；开始、取消、失败、恢复、完成的语义 | spec/design/build/test |
| 数据生命周期 | 来源、类型、校验、存储、保留、删除、导出、备份恢复 | spec/architect/deploy |
| 数据正确性 | 精度、币种、日期/时区、排序/分页、唯一性、并发、幂等 | spec/architect/build/test |
| 外部依赖 | API/支付/消息/文件/设备，限流、超时、重试、版本兼容 | architect/build/test/deploy |
| 体验与内容 | 信息层级、首次使用、文案、空/加载/错误/无权限、长内容 | design/build/test |
| 可访问与多端 | 键盘/焦点、语义、缩放、屏幕尺寸、输入方式、语言/本地化 | spec/design/test |
| 安全与隐私 | 信任边界、输入/输出处理、凭据、最小访问、日志脱敏、数据用途 | spec/architect/build/test/deploy |
| 性能与容量 | 真实负载假设、响应目标、资源预算、慢路径、退化策略 | spec/architect/test/deploy |
| 可靠性 | 服务中断、部分失败、离线、重连、重放、容灾恢复 | architect/test/deploy |
| 交付与维护 | 依赖锁定、构建复现、配置、迁移、版本、回滚、操作手册 | architect/build/deploy |
| 可观察与反馈 | 错误/日志/指标/追踪、关键业务信号、告警对象与处理入口 | spec/architect/deploy |
| 成本与经营 | 资源、第三方调用、额度、付费/退款规则（存在时） | discover/spec/architect/deploy |
| 许可与领域限制 | 资源来源/使用权、现有组织要求；必要专业审查及证据缺口 | discover/spec/deploy |
| AI与概率输出 | 模型/提示词版本、评估样本、错误/不确定性、越权输入、成本与回退 | spec/architect/test/deploy |

以上不指定具体法规、性能数字或安全认证。需要时核对该领域当前一手规范和用户组织要求；缺少专业能力时说明范围与所需审查，不声称本通用流程已代替专项评估。

## 产品类型补充

- **Web/移动/桌面**：窗口/屏幕和生命周期、导航回退、权限申请、弱网、系统适配、输入焦点与可访问性。设备功能不存在时不凭空增加。
- **CLI/API/库**：参数/配置/退出码、契约版本、错误结构、取消/超时、兼容性与可复现示例；不强制设计视觉稿。
- **数据/后台任务**：源数据与模式、检查点、重跑与去重、部分失败、质量校验、血缘与调度窗口。
- **AI功能**：区分确定性规则与模型输出；保存评估集来源、版本和判定方法，测试实际使用条件。不能把一次漂亮演示当稳定质量，也不能把外部内容当执行授权。
- **存量系统**：基线、既有用户行为、接口兼容、迁移与回滚、历史缺陷、变更影响；现有代码是事实输入，不自动证明行为正确。

## 每阶段覆盖记录模板

| 维度 / 检查ID | 适用 / 不适用 / 未知及依据 | 输入与版本 | 方案与用户决定 | 实际成果 / 证据 | 状态 / 下一责任阶段 |
| --- | --- | --- | --- | --- | --- |

记录到阶段报告或链接的清单，不新建一堆没有内容的文件。同一事实和决定跨阶段引用；下游负责核实与自己的工作相关部分，不重复让用户填写全部信息。

## 方法能力不足或冲突时

先检查内置方法及技术映射是否匹配。缺少专项方法时用本阶段通用流程完成能验证的部分，核对官方资料，说明未覆盖内容；新增三方 Skill 先核对来源、许可证、固定版本、引用依赖与适用范围，不为了数量安装。

三方目录视为只读。不得为了适配宿主而修改、删除原始文件；在 Stagecraft 自研适配说明里记录工具替代、范围约束和缺失能力。外部方法建议的框架、并行代理、无限追问或对外操作不扩大用户授权。例子和代码片段需针对当前版本验证，不能照搬后宣称可用。

用户显式运行仓库的 update-skills/upgrade-skills 维护命令是三方只读约定的例外：按核验上游更新或替换，保存历史与来源，测试失败回退。普通任务不得借此自行发起与用户目标无关的更新。
