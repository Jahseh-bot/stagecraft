## 用例设计与执行交接

记录用例集版本与路径、AC → TP → TC → 实际测试映射、评审记录和用户选择来源。逐用例记录执行状态、被测版本、环境、证据和缺陷；设计 ready 不等于执行 passed。详见 [用例模板](../references/test-case-design/assets/casebook.md)。

分别统计 ready / needs_revision / excluded，以及 passed / failed / blocked / not_run / skipped；提供范围内 AC 和约定用例总数作为分母，保留失败与回归历史。关键用例未就绪或未执行，明确阻断交付或发布判断。

## 阶段成果

可执行测试、AC/风险覆盖矩阵、运行日志、复现步骤、授权修复及回归证据、剩余缺陷与发布建议。

## 诊断、修复与复验

记录每次失败、假设、改动与复验；未执行的检查明确标注。

## 阻塞、风险和未完成项

没有关键证据不能标 completed；具体说明下一步所需条件。

## 下一阶段交接

deploy：传递测试修订版本、可发布判断、已知限制与必要部署后验证；阻断缺陷不能作为已通过交接。

记录下一技能名称、需读取文件、必须保留的决定、待检查风险与恢复入口。

## 本轮交付与停顿

记录当前提交版本、实际展示的产物/预览及待评审要点。展示后结束当前轮，状态保留 awaiting_review；下一阶段只注明名称。后续真实回复通过该版本后才能推进；修改后重新提交并再次等待。不得在报告中预填用户批准。
