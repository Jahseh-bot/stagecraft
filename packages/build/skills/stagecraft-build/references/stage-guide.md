# 开发实现详细工作指引

## 开始前

识别用户工作区改动、仓库约定、构建/测试命令、已评审PRD/设计/技术方案和目标环境。已有成果不足时补足本任务所需材料并评审；不因直接进入build而默默决定产品、视觉或技术方向。

将实现拆成可验收切片，列出 AC、设计/接口契约、依赖与测试。先建立原有行为/失败基线；无法运行时区分环境缺失和真实缺陷，不能先改大量代码再猜原因。

## 切片闭环

1. 明确本片输入、输出、状态与可观察验收，复用已确认方案。
2. 实现最小完整链路：UI/调用方 → 业务规则 → 数据/依赖 → 结果与错误反馈；只做本期范围。
3. 对新增行为或缺陷写能失败也能通过的行为检查；需要时应用TDD，避免只验证内部实现细节或假数据返回。
4. 实际运行相关静态检查、测试、构建和运行验证，记录具体环境/版本/命令。
5. 失败先定位根因，再修复和复验；每轮有新证据，遵守有限修复预算。
6. 展示切片效果和关键限制；影响产品行为、架构或视觉的变更回到用户讨论。

## 按改动类型检查

| 改动 | 实现与自检重点 |
| --- | --- |
| UI/交互 | 对照已选设计的层级、状态、响应式、焦点/键盘、文案与数据流；加载/错误/空态不是演示摆设 |
| API/业务规则 | 输入校验、认证授权、资源所有权、错误契约、事务与幂等、超时取消 |
| 数据存储 | 约束与索引、精度/时间、迁移兼容、历史数据、失败回滚、连接与资源释放 |
| 外部集成 | 真实契约、模拟边界、鉴权、限流/超时、重试副作用、失败告知；模拟成功不能当集成验证 |
| CLI/库 | 参数与配置优先级、输出/退出码、兼容性、错误提示、取消、安装与用例示范 |
| 移动/桌面 | 生命周期、系统权限、离线/重连、输入方式、平台差异、资源管理 |
| 后台/数据任务 | 检查点、重跑、去重、部分失败、输入质量、可观察进度 |
| AI功能 | 模型/提示词版本、输入边界、输出校验、超时/成本/降级、评估样本与未确定结果处理 |

读取技术映射中与实际栈匹配的方法，不引入其示例偏好的其他框架。依赖新增先核实当前兼容版本和用途，保留锁文件策略；避免顺手升级全项目。

## 代码审查与可维护性

检查最终差异是否与任务一致；删除本次无用临时代码和调试输出，保留用户工作；检查错误是否吞没、日志是否泄露、资源是否关闭、权限是否在可信层执行、公共契约是否无意变化。清楚的模块边界优先，不为假设未来制造抽象。

检查AC覆盖与实际运行效果；把原有失败、新失败、工具缺失和未测范围分别列明。不能删除有效测试、降低验收或只看进程启动来声称功能完成。

## 产物评审与交接

保存代码/配置、相关测试、运行说明、检查日志、截图或演示入口和AC映射。展示可用成果、设计差异、环境要求、数据初始化方式及剩余问题，等待用户评审具体版本后交给test。

临时服务记录进程与端口归属，清理自己创建且不需保留的资源；用户要求保留的预览说明如何访问/关闭。用户修改需求时重评影响，不把旧用例或旧批准当新版依据。开发自测不等同独立测试结论。
