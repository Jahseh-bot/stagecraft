# 逐题讨论与确认记录

## 原始原则

用户要求 npm 多包、单包单职责、独立闭环、任意阶段切入，最终加快产品开发。

## 部署补充

用户提出“部署呢”，已纳入 deploy，整体覆盖七阶段。单独使用 deploy 时无须先使用 build 或 test。

## Q1：谁执行阶段任务？

推荐已有 AI 编程工具执行，包提供 Skills、模板与脚本。用户回答：“可以，都按照你推荐的来。”因此执行模式已确认，且授权对可逆实现选择采用推荐默认值，不再逐项等待确认。

## 本轮采用的默认值

- npm workspaces；七包先交付安装器与工作流初版。
- Codex、Claude Code 作为首批技能目录适配。
- 优先对 test 做真实效果验证，之后验证 spec/build/test 串联。
- deploy 先提供 Docker Compose 单机流程。
- 原生 Node.js 安装器，构建时复制进包，发布包无阶段间依赖。
- 使用人可读的 Markdown 交接；安装冲突保留原文件。

以上由代理在用户授权下选择，可根据真实试用调整。暂定品牌不是名称归属确认；本轮未进行 npm 公开发布、真实服务器部署或外部付费操作。

## 用户纠正：自动推进才是核心

用户指出当前方案与直接使用 coding agent 差异不足。期望例如输入 PRD 后，主动澄清技术栈、架构和关键问题，再自动执行完整目标链路，仅在必要时人工介入；其他入口同理。此前“按推荐来”不应解释为放弃自动编排。已用 ADR 0002 替代原执行边界，尚未实现运行器。

## 继续实现与上游方法复用

用户要求先跑通 PRD 到可运行版本，并补充各阶段可采用市场成熟 Skills，例如 Matt Pocock。已实现 runner 和可替换的上游 profile，完成真实 Codex 演练；执行与技能来源详情见 architecture.md、skill-sources.md 和 live-drill.md。
