## 真实步骤

1. Codex 第一次调用因本机默认模型与 CLI 不兼容及本地 MCP 故障而失败。运行器进入 waiting_input，保存错误。
2. 采用 `STAGECRAFT_CODEX_ISOLATED=1` 继续：不修改用户全局配置，使用 CLI 默认模型与现有认证。真实 Agent 提出精度问题。
3. 演练按推荐值回答：API 不强制舍入，页面最多两位小数并去尾零。样例答案由本次演练提供，不代表真实业务用户的决定。
4. 接入固定上游 Skills 后继续，Agent 生成 Node.js 无依赖方案、测试 seam、验收命令与启动契约；演练确认该方案。
5. 一次实现调用遇到 429，保留阻塞状态后有限重试。随后真实 Agent 生成 HTML/CSS/JS、Node HTTP 服务和测试。
6. `tooling/live-drill.mjs` 显式将公式中的 +32 改成 +31，以测试故障处理。这是故障注入，不是将 Agent 原始实现描述为错误。
7. 运行器实际执行测试，13 项中 5 项失败（例如 0 摄氏返回 31 而非 32），转入 repair。演练通过 AbortSignal 在修复开始前暂停并持久化检查点。
8. 使用标准 CLI resume 启动新进程。没有重问精度和架构，真实 Codex 读取失败证据并修复公式。
9. 冻结测试文件哈希保持不变；13/13 行为测试通过，附加语法与单文件复核均通过；实际启动得到 HTTP 200 / `ok`，运行器随后关闭烟测服务并记为 completed。

自动化回归测试另外验证了真实 CLI SIGINT 和子进程清理；本次真实模型演练的中断是显式 AbortSignal。

## 复现

参照 runner/README 启动同一 PRD到一个新的项目目录，回答其实际问题并审阅其计划。需要故障注入时，仅对该演练样例使用 `tooling/live-drill.mjs <run-directory>`；它在批准方案后执行，修改样例公式，并在失败转修复时暂停。之后用标准 resume 继续。

模型生成结果可能不同；故障脚本找不到约定公式会报错，不会假装注入成功。常规自动化测试不依赖模型服务或付费调用。
