# Stagecraft 官方网站

## 用户要求
用 npm 已发布的 Stagecraft 本身构建一个独立的 Stagecraft 官网项目。网站介绍 Stagecraft，提供面向没有开发经验用户的详尽使用教程和更新文档。参考 Vue 官方站 https://vuejs.org/ 和 https://vuejs.org/guide/introduction.html 的文档体验。简体中文优先。

## 已确定的产品决定
- 当前项目根目录就是新官网项目。source-material 是现有 Stagecraft 仓库的资料快照，只读参考，不要修改。
- Stagecraft 版本 0.3.0，npm scope @gaaraa，GitHub https://github.com/Jahseh-bot/stagecraft 。0.3.0 已公开发布；0.2.0 是本地 tarball 分发。不可臆造新版本、发布日期、用户数量、赞助商、用户评价、云部署能力。
- 主受众是完全没有开发经验的人。教程要完整保留 source-material/npm-usage.md 的操作、示例、预期结果、人工确认、恢复、排错与平台限制，拆分成可浏览的小节，不能只提供一个外链或三行命令。
- 官网本身是静态文档站，不需要账号、后端、数据库、支付或分析追踪。优先 Vue 3 + 稳定 VitePress，自定义主题和首页。核实依赖版本兼容并保存 lockfile。
- 此次交付为可本地运行并能构建静态文件的完整项目，不需要 Docker、云服务、GitHub 推送或购买域名。

## 页面与内容
1. 首页：Stagecraft 标识与原创几何 logo，顶栏（指南、工作流程、CLI 参考、更新记录、GitHub、搜索、主题切换）；有辨识度的 hero，标题表达从需求到可运行应用，简短介绍，开始使用和了解工作流程按钮。首页展示真正的 npx 命令、需求→澄清→方案确认→实现→测试修复→交付/本机部署过程，说明人的确认节点。至少包含能力介绍、三种使用入口、入门引导和最新版本入口。
2. 指南：什么是 Stagecraft、准备环境、第一次运行（可拆分需求文件与启动任务）、回答问题与确认方案、查看成果与启动网页、暂停恢复、已有项目测试、本机部署、故障排查。Markdown 为主，左侧分组导航、右侧本文目录、上下篇导航、代码块复制。
3. CLI 参考：runner/build/test/deploy 等包用途、实际公开命令与参数、runDir/answers.json 示例、常用退出码。明确 init 仅安装技能。
4. 工作流程：用清楚的视觉流程解释阶段与人工审批，可用语义 HTML/CSS，不依赖外部图片。
5. 更新记录：依据 CHANGELOG.md，中文显示 0.3.0 和 0.2.0，不捏造日期。说明如何固定版本、恢复旧任务保持版本一致。
6. 404 页面与返回首页链接。

## 视觉和交互
参考 Vue/VitePress 的可读性和信息架构，保留 Stagecraft 自己的品牌。偏清爽的白色/石墨背景，克制的蓝绿或薄荷色强调，细边框、充足留白、清楚的中文字体层级。首页必须有专门设计，不只套默认三张卡片。可用终端示例与阶段流程作主视觉，无需图库。暗色模式应认真适配，不出现低对比度文字。手机端导航、搜索、表格和长代码块可用，无横向页面溢出。尊重 reduced-motion。所有按钮/链接须可工作，不留 placeholder。
- 站内本地搜索支持真实文档内容，优先 VitePress local search，支持搜索词如“安装”“暂停”“Docker”。
- 深浅主题切换、移动端导航、代码复制、目录锚点、教程分页正常。
- 无需联网加载字体或远程图片。正文提供真实官方 Node/Codex/Docker 参考链接。
- 页面标题、描述、favicon；不要虚构上线域名。

## 验收与交付
- npm install / npm ci 后，npm run dev 能启动；npm run build 能生成静态站点；npm run preview 可预览产物。README 用中文说明开发、构建、添加文档/版本记录和产物位置。
- 建立有意义的验证：实际生产构建、关键页面输出/内部链接、教程关键步骤完整、浏览器导航和主题/搜索/移动端菜单（环境能使用浏览器时做真实交互测试）。不做镜像实现的空测试。
- 本地 HTTP smoke 在固定未占用端口验证首页包含 Stagecraft。不自动占用公网接口。
- 创建清晰可维护的文件结构与 .gitignore，忽略 node_modules、构建产物、.stagecraft 运行记录。不要把本地绝对路径写入网站正文。
- 计划中给出具体检查命令、测试文件路径和启动命令。若技术问题有合理默认，按以上明确决定推进，无需再次询问品牌语言、技术栈、域名等已确定事项。
