# 从需求到交付，每一步都有依据

Stagecraft 调用你本机已登录的 Codex CLI 工作。它会自动推进执行阶段，在需要做决定时停下来。下面的标记表示你参与的位置，不是实时任务状态。

<StageFlow />

## 先确认要做什么

需求文件描述“给谁用、做什么、外观、不做什么、怎样算完成”。有歧义时进入澄清阶段，程序输出问题 id 和建议。你通过答案文件回答，而不是直接在终端输入“同意”。

[跟着示例写第一份需求](/guide/requirements)

## 在实现之前确认方案

方案包括技术栈、任务、测试文件、验收命令和启动方式。看到 `approve_plan` 后先检查它们是否符合你的要求；可以回答 `yes`，或用 `revise:具体修改` 要求调整。已经确认的决定会随运行记录保留。

[学习如何提交答案](/guide/confirmation)

## 用真实执行检验应用

实现后运行批准的检查命令，并按计划临时启动应用做本机 HTTP 检查。失败时根据日志尝试修复，修复预算耗尽后请求人工介入。验收文件和命令属于已确认的契约，不能为了通过检查自行放宽。

测试通过后会关闭临时服务。交付说明包含实际启动命令，你需要再次启动应用才能持续使用网页。

[找到成果并打开网页](/guide/delivery)

## 暂停与恢复

按 `Ctrl + C` 后等待程序保存状态并退出。保留项目和 `.stagecraft` 目录，下次用创建任务时的版本恢复。遇到等待输入，先回答当前问题；遇到错误，保留日志并解决原因。恢复不等于忽略错误重来。

[暂停与恢复操作](/guide/resume)

## 从已有项目开始

- **测试入口**：只读检查 → 确认测试计划 → 按需补测试 → 执行检查 → 报告结果或在预算内修复。audit 不自动修业务代码，repair 允许修复。
- **部署入口**：发现配置 → 回答关键问题 → 确认配置草稿（`approve_setup`）→ 生成缺失文件 → 确认部署方案（`approve_plan`）→ 本机 Compose 启动 → 健康检查。

这两个入口都不需要重新写 PRD。部署保留现有文件，不会凭空发布到云端。缺少事实时会停下来，而不是假定部署成功。

[已有项目测试](/guide/existing-project) · [本机部署](/guide/deployment)
