# 从需求到交付，每一步都有依据

<StageFlow />

## 从任意阶段切入

已有代码可直接测试，已有明确需求可直接实现。缺少前序 Stagecraft 报告时，只补足当前阶段必要输入，不强制重走全流程。

## 每个阶段自己闭环

检查输入 → 约定验收 → 执行 → 真实验证 → 诊断修复 → 复验 → 保存证据。关键方向先提出方案、推荐理由并等待用户选择；确认后的实现细节与阶段交接自动完成。连续修复有预算，不用无限重试或削弱验收来掩盖问题。

## 沿用同一交接记录

`.stagecraft/workflows/<id>/` 保存目标、入口/终点、AC、决定、成果路径、证据与下一步。下一阶段读取同一记录；发现文件改动时将相关结果标为 stale 并重新验证。切换 agent 后也能从文件继续。

## 以用户目标决定终点

用户要求做到测试通过时，在已安装技能之间继续；只要设计时就交付设计。部署要求明确目标与授权，完成后必须核对实际发布版本和访问结果。未安装后续技能时给出准确交接，不声称已经执行。

## 选择方案与评审产物是两道环节

每个阶段先讨论尚未决定的方向，推荐项在前，允许自由补充；执行后展示实际产物与证据，具体版本评审通过才进入依赖它的后续阶段。测试用例先评审再执行，发布清单先评审再上线。已有明确选择可以复用，不能用旧评审批准修改后的新版本。

按需要精简流程：没有界面的任务不强制视觉设计，单点修复不重做产品探索。流程适配由 agent 说明依据，保持任务目标和验收标准不变。[复制完整调用提示词](/guide/first-run#prd-to-deploy)。
