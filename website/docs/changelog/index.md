# 更新记录

依据项目 CHANGELOG 整理。以下是产品版本，不是官网依赖版本。

## 0.5.0 · 全链路变更联动（发布中，2026-10-22）

- 需求、设计、架构、代码、测试、文档与发布资料双向关联；从任何阶段发起变更都检查所有受影响产物。
- 新增关联图与变更单（CR），记录版本、影响范围、实际同步、验证和评审；旧批准与旧测试证据不能直接复用。
- 新增 trace/change/change-close 助手命令；启用关联后使用 v3 工作流，旧助手会拒绝读取；新助手仍支持普通 v1/v2 历史。
- 每阶段修订后仍展示并结束本轮，等待用户评审；测试用例先评审再执行，不自动部署。
- 七阶段技能、报告模板和官网提示词同步，三方方法保持原样。已安装用户按[升级教程](/guide/upgrading)更新。

## 0.4.2 · 阶段交付后结束本轮（npm 已发布）

- 七阶段每次展示成果后结束当前轮，等待用户在后续回复评审具体版本，再进入下一阶段讨论。
- 修改意见留在当前阶段，修订并重新展示后再次等待；澄清回答和方案选择不再混同成果验收。
- 创意与 PRD 草稿从对应阶段开始，不直接跳到开发；七个入口、共享协议和官网提示词同步。
- 八个 npm 包统一为 0.4.2，包含 release 最外层 skills 目录；三方方法保持原样。
- 已安装用户按[升级教程](/guide/upgrading)更新并重新加载技能；[固定版本安装](/guide/packages)提供七条可复制命令。

## 2026-10-21 · 官网教程重整与三方方法维护

- 当前安装主路线统一为 GitHub Skills；重整时移除尚不可用的 npm 命令；同日发布 0.4.1 后补齐固定版本安装方式。
- 从环境、七阶段安装、PRD 输入，到逐阶段讨论、产物评审、测试用例、部署验收和恢复，按真实使用顺序重整。
- 区分产品项目中的 `npx skills update` 与源码仓库的两条维护命令。
- 采纳前端设计、端到端测试和 SQL 优化三项来源替换，更新 Docker 来源锁及四项许可证分发。
- 修复仓库改名、入口用途匹配与多行描述处理，记录被拒绝候选版本；普通产品执行仍保持三方原文。
- 维护后的 90 项测试及 Skills 审计通过；不代表全市场比较或真实任务效果对照实验。

## 0.4.1 · 方法编排与逐环节方案讨论（npm 已发布，2026-10-21）

八个 `@gaaraa/*@0.4.1` 包已从本次重新生成的 tarball 发布，七阶段技能与兼容 runner 版本一致。安装方式见[阶段包教程](/guide/packages)。

- 产品范围、模块、交互、风格、技术架构和部署目标先给选项与推荐理由，等待用户选择。
- 确认后自动开发、测试、修复和交接，复用已确认决定与明确委托。
- 七个 Skill、交接模板和官网可复制提示词同步更新。
- 各阶段方法从可选参考升级为按条件执行的编排，记录具体成果与证据；新增 grill-with-docs 和 domain-modeling 固定版本及完整依赖。

- 每个阶段与决策环节先讨论；选项 1 始终为最推荐方案并解释理由，最后保留自由文字补充。确认当前环节后执行，再准备下一环节方案。

- 测试阶段新增内置用例设计 Skill：拆点、生成、补漏、评审先于测试执行；逐用例关联 AC、结果和证据，支持过程中讨论业务规则与风险。

- 各阶段新增产物展示与版本评审门禁；交接助手 v2 保存内容快照、用户意见，支持修改后重新评审和下游失效检查。旧 v1 状态备份后进入重新检查流程。

- 全阶段增加详细执行指引、跨阶段适用性矩阵和三方只读适配说明；新增可重复 Skills 扫描与三方源完整性校验，正常产品执行保持三方原文；显式维护按核验结果更新或替换。

- 新增仓库维护命令 update-skills / upgrade-skills：核验上游更新、联网候选筛选、版本与哈希同步、测试失败回退，以及预检与备份恢复。

## 0.4.0 · npm 已发布

- 七阶段改为当前 coding agent 原生执行的 Skills，职责内自主验证、修复和交接。

## 固定版本与恢复旧任务

```sh
npx --yes @gaaraa/runner@0.3.0 --version
npx --yes @gaaraa/runner@0.3.0 resume --run "$RUN_DIR"
```

恢复旧任务时使用**创建该任务时的版本**。不要中途换成 `@latest`；0.2.0 本地任务应保留对应 tarball 和原运行环境，不要把上面的 0.3.0 命令直接用于旧任务。保留整个项目和 `.stagecraft` 记录，新项目再考虑新版本。
